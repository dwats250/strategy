# FAMILY AUTONOMY PROTOCOL · v1.0 · 2026-08-27

A standing protocol so future owner/HELM instructions need not micromanage phases
within a single research family. Authorized by owner/HELM charge 2026-08-27. This
governs **how** an authorized family is worked; it does not itself authorize any
family. It sits under `docs/conventions.md` (the lab rules) and does not weaken any
firewall (§g), the repository boundary (§i), or the model lanes (§j).

## Scope of autonomy

Within **ONE explicitly authorized family**, the orchestrator may proceed
autonomously through:

1. recover literature / provenance;
2. freeze the **simplest falsifiable baseline** (pre-registration);
3. implement deterministic support;
4. self-test (deterministic, synthetic);
5. run the **authorized development baseline** (once);
6. produce standard evidence (tear sheet / regression / robustness);
7. update the research ledger and map;
8. classify and **kill a failed family** without asking permission.

Freeze and result are committed as separate, pushed commits so the pre-registration
stays provable (freeze pushed before any outcome; results by dated amendment).

## Mandatory STOP conditions

Stop and return to HELM at any of:

- **A. FAMILY DEAD** — the baseline fails its frozen kill gate. Record it, kill it,
  stop. (This is an autonomous *conclusion*, not a request for permission — but no new
  family is opened without a fresh charge.)
- **B. EDGE CANDIDATE — VALIDATION DECISION REQUIRED** — the baseline passes every
  frozen gate. Stop before any validation.
- **C. MATERIAL AMBIGUITY / DATA BLOCKER / NEW PROVIDER REQUIRED** — a semantic
  ambiguity that cannot be resolved cleanly, a data/corporate-action issue that cannot
  be established without guessing, or a need for data not in the repository.
- **D. AUTHORITY BOUNDARY** — anything touching a frozen record, the repository
  boundary, a firewall, or scope beyond the authorized family.

## Hard prohibitions (never autonomous)

- No autonomous **validation** and no **holdout** access.
- No **transition into a different hypothesis family** (each family needs its own
  charge).
- No **post-failure rescue filters** and no **broad parameter optimization**.
- No reuse of a consumed validation window as another family's confirmation.
- No new confirmation data fetched or inspected.

## Development allowance

Default: **at most FOUR interpreted development configurations** per new family before
HELM review, unless the family charter sets a **smaller** ceiling (the smaller wins).
A **failed baseline does not automatically earn** the remaining configurations —
config 1 failing is a family-dead signal, not a licence to spend 2–4.

## Evidence & discipline (unchanged lab rules)

Screened corpus primary, raw sensitivity; primary metric declared before outcomes;
classification thresholds and cost/robust-SE conventions frozen before outcome access
(no shopping); determinism verified; every interpreted run gets a ledger row
(`docs/conventions.md` §f) and a research-ledger entry. Frozen records are never edited
in place (dated amendments only, §b/§c).
